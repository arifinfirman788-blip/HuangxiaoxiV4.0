节点状态计算伪代码

function calcNodeStatuses(allNodes, now): currentNode = null for i = 0 to allNodes.length - 1: node = allNodes[i] nextNode = allNodes[i + 1] // 可能为 null if now < node.startTime: // 当前时间早于该节点 → 该节点及之后全部"未开始" node.status = "未开始" // 后续节点也全部"未开始"（break） break else if nextNode == null || now < nextNode.startTime: // 当前时间 ≥ 该节点时间，且 < 下一个节点时间 // → 该节点"进行中" node.status = "进行中" currentNode = node // 特殊: 当天最后一个节点 + 已过零点 if isDayLastNode(node) && now >= endOfDay(node.date): node.status = "已完成" currentNode = null break else: // 当前时间 ≥ 该节点 且 ≥ 下一个节点时间 // → 该节点"已完成" node.status = "已完成" return currentNode // 首页展示该节点; null 则展示第一个"未开始"节点

8已识别的逻辑漏洞及补充

# 漏洞描述 补充方案
1 原流程仅判断"是否有行程"，未区分行程状态 已修复 改为判断"是否有进行中的行程"
2 节点状态仅对比精确相等（=），忽略了时间区间（如 08:00 到 10:00 之间应为进行中） 已修复 改为区间判断：t(n) ≤ now < t(n+1) 时，节点n为进行中；之前节点全部已完成
3 结束行程后首页未明确显示内容 已修复 结束后首页显示"暂无进行中行程"
4 未处理"行程自然结束"场景（最后一天最后节点完成后） 已补充 最后一天最后节点过零点后，行程自动标记已完成
5 未限制同时只能有一个进行中的行程 已补充 开始新行程前检查是否有其他进行中行程，有则阻止并提示
6 首页未处理"全部未开始"的情况（如 07:00 进入，第一个节点 08:00） 已补充 当无进行中节点且有未开始节点时，展示第一个节点并标注"即将开始"
7 未考虑跨天间隙（当天最后节点结束到次日第一个节点之间） 已补充 当天24:00后当天节点全部完成，次日节点根据时间判断状态
8 首页卡片类型遗漏了自定义活动（free_time）和团餐（group_meal） 已补充 补充 free_time 类型的卡片展示
9 未说明"已完成"行程是否可重新开始 待确认 需产品确认：已完成行程是否支持重新开启
